# DIS 챌린지 포인트 3가지

## 1. “재생됐다고 나오는데 왜 소리가 안 날까?”

봇은 음성 채널에 들어오고 재생 안내도 보냈지만 실제로는 음악이 나오지 않았습니다. 연결 여부와 곡 검색 성공만 보지 않고, 음원 데이터를 가져오는 단계의 로그와 인증 상태를 확인했습니다. 외부 음원 요청 방식의 호환성을 보완해 재생을 복구했고, 요청을 받은 상태와 실제 재생 실패를 구분해 안내하도록 개선했습니다.

## 2. “작업이 끝났는데 답변할 사용자를 놓치면 안 된다.”

명령을 받는 부분과 음악을 처리하는 부분을 나누면서, 처리 결과를 원래 요청에 돌려주는 순서도 정리했습니다. 답변할 위치를 먼저 저장하고 작업을 보내도록 바꿨으며, 작업이 빨리 끝나도 이 순서가 지켜지는지 테스트했습니다.

## 3. “기능 코드를 바꾸지 않았는데 빌드가 막혔다.”

외부 라이브러리 저장소가 필요한 설명 파일 대신 웹페이지를 반환해 빌드가 실패한 문제에 대응했습니다. 원인을 확인한 뒤 같은 버전의 공식 배포 파일을 받도록 바꾸고 검증값을 확인했습니다. 변경 이후 자동 빌드와 서버 배포 성공을 확인하며, 서비스 운영에는 기능 코드뿐 아니라 전달·실행 과정도 포함된다는 점을 배웠습니다.
