이동욱·남정호·황준일의 공개 이력서·프로젝트 글을 직접 읽고, 요약과 상세의 분리, 실제 불편에서 출발하는 서술, 판단·결과·남은 범위의 설명 방식을 비교했다. [REFERENCE_ANALYSIS.md](REFERENCE_ANALYSIS.md)에 원문 고정 커밋과 구체적인 적용 이유를 기록했다.

외부 작성자의 트래픽·성능·회사 경험은 가져오지 않았다. 공개 문서의 서술 방식을 분석한 것이며, 해당 작성자의 경력이나 채용 결과를 독립적으로 검증한 것은 아니다.

## 3. HTML·PDF 확인

실제 Chromium으로 로컬 HTTP 미리보기를 열어 다음을 확인했다.

- 데스크톱 1440px, 모바일 390px에서 가로 넘침 없음.
- 목차를 눌러 해당 챕터로 이동하는 동작 확인.
- JavaScript 오류 없음. 외부 폰트·CDN·외부 스크립트 요청 없음.
- A4 출력: **이력서 1쪽**, **DIS 상세 포트폴리오 6쪽**.
- 두 PDF에서 한글 텍스트·이름·지인 약 30명 문장이 추출되는지 확인.
- 이력서와 포트폴리오 첫/마지막 페이지를 이미지로 렌더링해 표·본문·꼬리말 위치 확인.
- PDF의 짧은 잔여 페이지가 생기지 않도록 이력서의 중복 소개를 줄임.
- 원고와 검토 문서의 상대 링크, 생성 HTML의 소스 연결, 공백 오류 확인.

이번 작업에서 Java 기능 테스트를 새로 실행하지는 않았다. 기능 코드가 바뀌지 않았으며, 본문의 구현·검사 범위는 소스와 과거의 CI 결과를 근거로 확인했다.
