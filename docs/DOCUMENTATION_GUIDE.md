# README와 문서 작성 기준

이 기준은 처음 보는 개발자가 프로젝트를 이해하고, 실행하고, 검증할 수 있게 문서를 유지하기 위한 것이다. 루트 README, 디렉터리 README, 현재 구조·운영 문서에 적용한다.

## 품질 기준

| 기준 | 문서에서 확인할 것 |
| --- | --- |
| 목적이 분명하다 | 첫 문단에 프로젝트·디렉터리의 역할과 대상 독자가 나온다. |
| 실행을 재현할 수 있다 | 사전 도구, 작업 디렉터리, 설정, 명령, 정상 결과, 종료 방법을 연결한다. |
| 코드와 일치한다 | 명령 옵션, 버전, 기본값, 포트, 서비스명에 소스·설정 링크가 있다. |
| 근거를 구분한다 | 구현된 기능, 테스트의 존재, 실제 실행 결과, 계획을 구분한다. |
| 다음 문서를 찾을 수 있다 | 부모 문서·관련 코드·상세 절차로 가는 상대 링크가 동작한다. |
| 유지보수할 수 있다 | 상세 정책은 담당 문서에 두고, 과거 기록은 현재 설명과 구분한다. |

## 문서별 구성

루트 README는 **소개 → 사용 예 → 빠른 시작 → 구조 → 검증 → 운영·문서 링크** 순서로 작성한다. 실제 이미지가 있으면 기능 옆에 넣되, 확인되지 않은 실행 화면·성능 수치·성공 배지는 만들지 않는다.

앱 README는 역할, 실행 진입점, 주요 호출 흐름, 의존 서비스, 설정·테스트·로그 확인 링크를 담는다. 라이브러리 README는 사용 앱, 제공 타입·구현, 책임 경계, 확장 시 함께 수정할 코드를 설명한다. 디렉터리 인덱스는 어떤 작업에서 어느 파일을 읽는지 안내한다.

절차 문서는 저장소 루트와 서버 release 디렉터리 중 어디에서 명령을 실행하는지 명시한다. Linux 셸과 PowerShell 명령이 다르면 둘 다 제시한다. `.env`를 Compose가 읽는 것과 IDE의 Java 프로세스가 환경 변수를 받는 것을 구분한다. 예제에는 실제 자격 증명 대신 변수명·설정 여부만 보여 준다.

## 현재 설명과 측정 결과

- 기본값은 `.env.example`, Compose, 앱의 `application*.yml`, Properties 클래스와 대조한다. 앱 기본값과 Compose 주입값이 다르면 실행 경로를 명시한다.
- 예약 작업은 실제 `fixedDelay`·cron과 활성화 조건을 기록한다. 예상 호출량에는 외부 호출 시간·실패·재시도의 전제를 붙인다.
- 테스트 파일의 존재와 이번 커밋에서 테스트가 통과했다는 사실을 구분한다. 실행 결과는 보고서나 CI artifact로 연결한다.
- 성능 결과에는 코드 버전, 설정, CPU·메모리, 데이터 크기, 목표·실제 주입률, 반복 횟수, 원본 결과, 측정 경계를 남긴다.
- 명령 접수, worker 결과, 실제 음성 프레임, Discord 사용자 청취를 같은 성공 지표로 취급하지 않는다.
- `internal/`의 과거 보고서는 현재 구현에 맞춰 다시 쓰지 않는다. 인덱스에서 역사적 기록임을 표시하고 현재 문서로 연결한다.

- [ ] 필요한 JAR 빌드·외부 서비스·권한·설정 순서를 빠뜨리지 않았다.
- [ ] 실행 후 확인할 상태와 로그 위치를 제시했다.
- [ ] 파일 링크·문서 내부 링크·그림이 실제로 존재한다.
- [ ] 현재 기능, 검증 범위, 계획과 과거 기록이 구분된다.
- [ ] 배포·재처리·데이터 삭제 명령은 효과와 적용 환경을 설명한다.
- [ ] 앱을 실행하지 않은 경우 실행 성공으로 표현하지 않는다.
