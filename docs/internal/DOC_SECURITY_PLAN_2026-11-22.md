# README·문서 최신화 및 노출 위험 정리 계획

2026-11-22. 지난 문서 PR #29가 main에 병합되지 않아 기본 README는 이전 구조를 표시하고 있었다. 이번 작업은 PR 안의 설명을 보강한 뒤 검증·main 반영까지 확인한다.

## 확인된 문제

1. 전체 그림이 앱·공개 진입점·데이터 경계를 구분하지 않아 Maple의 내부 HTTP와 음악·주식 RabbitMQ 경로를 읽기 어렵다.
2. Compose 관측성 서비스 6개의 포트가 호스트 IP 없이 게시된다. 기본 배포에서도 외부 인터페이스에 열릴 수 있다.
3. Git ignore가 `.env.production`, `ngrok.env` 등 일부 비밀 파일명을 막지 않는다.
4. preflight는 중첩 번들을 읽지 않고 API_KEY·WEBHOOK 일부를 대조 대상에 넣지 않으며, 번들이 없어도 검사가 완료된 것처럼 보일 수 있다.
5. `.env.example`의 사용자 수는 2, Compose fallback은 4인데 지난 문서는 둘 다 4라고 적었다. 예제와 Compose를 4로 통일하고 standalone 함수 기본값과 구분한다.

## 수정과 완료 기준

- README는 소개·전체 그림·사용자 흐름·보안 경계·실행·검증 순으로 정리한다. Mermaid 원본과 렌더한 SVG를 함께 관리한다.
- 현재 아키텍처·모듈·DB·보안·운영 문서를 연결한다. 과거 문서는 현재 실행 지침으로 연결하지 않고 읽기 전용 기록임을 명시한다.
- 관측성 포트는 loopback 기본값으로 제한하고 Git 제외 규칙을 보강한다. 기존 DB/Grafana 비밀번호를 `.env`만으로 바꿀 수 있다고 안내하지 않는다.
- 공개 파일·시크릿 파일명 이력을 값 출력 없이 검사하고 preflight의 PASS/FAIL/SKIP 경계를 명확히 한다. 이것을 전체 이력 비밀 탐지·침투 테스트·실서버 보안 인증으로 과장하지 않는다.
- 변경된 안전 기본값·검사 누락을 회귀 테스트하고 Compose 예제의 실제 변환 결과를 검사한다. SVG 렌더·문서 링크·CI 확인 후 main README의 이미지 경로와 내용을 재확인한다.

운영 비밀값 회전, 과거 Git 이력 삭제, 운영 DB 변경은 이 문서 정리의 자동 작업에 포함하지 않는다. 실제 비밀 노출이 발견되면 값을 출력하지 않고 종류·위치·필요한 회전 조치를 별도로 보고한다. 관리용 포트의 로컬 제한은 인증 자체를 대신하지 않으며 Docker socket을 사용하는 Alloy의 권한과 신뢰한 프록시의 로그 보관은 운영상 남는 경계다.
