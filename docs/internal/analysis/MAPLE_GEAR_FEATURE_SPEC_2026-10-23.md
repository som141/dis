## 1. 사용자 여정

기본 검색은 넥슨 계정 연결이나 사용자 개인 API 키를 요구하지 않는다.

```text
/아이템 캐릭터:예시히어로
→ 서비스의 일반 API 키로 닉네임 → OCID → 직업·월드·현재 장비 조회
→ 입력한 캐릭터를 기준으로 개인 패널
→ 부위·아이템 다중 선택 또는 전체 선택
→ 기준 예산 → 70~130% 검색 범위 확인
→ 경매장 제공자 검색 → 스펙 필터·지원 모델 점수·가성비
→ 기간 알림 선택 → 조건에 맞는 새 매물 DM
```

선택적으로 계정을 연결하면 내 캐릭터 목록 선택·본인 확인과 동의 범위의 개인 데이터 기능을 제공한다.

```text
/api
→ 비공개 웹 연결 링크
→ 웹에서 Discord 로그인·링크 발급 계정 일치 확인
→ NEXON Open ID 로그인·정보 제공 동의
→ UID·동의 scope·암호화한 access/refresh token을 Discord 계정에 연결
→ /아이템 캐릭터:예시히어로 실행 또는 내 캐릭터 목록에서 선택
```

사용자의 개인 API 키를 자동 발급·수집하지 않는다. `/api`는 계정 연결 관리용이며 키 입력을 필수로 만들지 않는다. 일반 공개 API의 서비스 키와 Open ID 사용자 토큰은 별도 인증 수단이다.

**외부 연동 상태:** Open ID는 지정된 프렌즈·애플리케이션 등록·공개 서비스 검수가 필요하다. 승인 전에는 실제 넥슨 연결을 켜지 않는다. 넥슨 로그인과 캐릭터 조회가 성공해도 경매장 인증을 성공으로 간주하지 않는다. 서버용 경매장 검색·주기 조회 권한은 기존의 별도 확인 항목이다.

## 2. 기능 범위

| ID | 기능 | 동작·완료 기준 |
| --- | --- | --- |
| F01 | `/api` 연결 시작 | 5분 유효 일회용 웹 링크, Discord에는 키 입력 필드 없음 |
| F02 | 웹에서 본인 확인 | Discord OAuth2 로그인 ID와 링크 발급 사용자 ID 일치 확인 |
| F03 | 넥슨 로그인 연결 | Open ID 로그인·동의 → 사용자 UID·실제 scope 확인, access/refresh token 암호화 저장 |
| F04 | 연결 관리 | 웹에서 재동의·연결 해제, 토큰 자동 갱신, 철회 시 grant가 필요한 작업 중지 |
| F05 | 닉네임 기준 조회 | `/아이템`의 필수 문자열 옵션 `캐릭터` → OCID·snapshot. 일반 조회는 서비스 키 사용 |
| F06 | 부위·아이템 선택 | 착용 조건을 반영한 카탈로그, 여러 아이템 선택, 전체 선택/해제, 선택 수 표시 |
| F07 | 예산 범위 검색 | 기준 예산 B의 0.7B~1.3B를 포함 경계로 검색, 실제 적용 범위 표시 |
| F08 | 추가 스펙 조건 | 별·잠재 등급·크뎀 등 지원된 구조화 필터. 미지원 필터를 조용히 무시하지 않음 |
| F09 | 검색 결과 | 판매 상태·가격·옵션·관측 시점·원본 이동 경로, 지원 후보의 개인 점수·가성비 |
| F10 | 기간 감시 등록 | 체크박스로 켜기, 기간 1일/3일/7일 중 하나, 활성화 전 조건 최종 확인 |
| F11 | 좋은 매물 판정 | 하드 필터 AND 개선량·가성비 기준, 판정 모드 명시 |
| F12 | 신규 매물 알림 | 첫 조회는 기준선, 이후 처음 관측한 적합 매물만 알림, 동일 매물 중복 억제 |
| F13 | 감시 관리 | 목록, 일시정지·재개·수정·종료, 남은 기간·마지막 정상 조회·지연 사유 |
| F14 | 알림 수신함 | 알림 내역 보관, DM 차단 시 수신함에서 확인. 공개 채널로 자동 전송하지 않음 |
| F15 | 대상 캐릭터 고정 | 검색·감시에 요청자 Discord ID와 대상 OCID를 별도 저장. 다른 캐릭터 요청이 기존 감시 대상을 바꾸지 않음 |
| F16 | 내 캐릭터 확인 | 동의받은 계정 캐릭터 목록에 OCID가 있을 때만 본인 캐릭터로 표시 |

자동 구매·입찰, 판매 가능 보장, 실시간 전체 경매장 관측 보장, 환산 사이트 내부 API 사용은 포함하지 않는다. 웹 연결과 Discord UI는 계산 모델 지원 범위와 별도로 구현한다.

## 3. 계정 연결과 `/아이템`

### Discord `/api`

```text
넥슨 계정 연결 관리            [본인에게만 표시]
닉네임 공개 조회: 로그인 없이 사용 가능
넥슨 계정: 연결 안 됨
경매장 검색: 제공자 연결 확인 필요

[웹에서 넥슨 계정 연결 ↗] [연결 상태 새로고침]
```

### 별도 웹사이트

```text
1. Discord로 로그인 → /api를 실행한 계정과 일치 확인
2. [넥슨ID 로그인] → 넥슨 화면에서 로그인·정보 제공 동의
3. 서버에서 인가 코드를 토큰으로 교환하고 사용자 UID·실제 동의 scope 확인
4. Discord ID ↔ (Nexon issuer, client ID, UID) 매핑·토큰 암호화 저장

[연결 상태] [재동의] [연결 해제] [Discord로 돌아가기]
```

일반 사용자에게 API 키 발급·복사를 요구하지 않는다. 토큰은 서버에서만 보관한다. 계정 매핑은 지속할 수 있지만 권한은 무기한이 아니다. 가이드 설명은 access 30분·refresh 14일이며, 서버는 실제 응답의 만료 시간을 사용한다. 갱신 응답의 새 refresh token도 원자적으로 교체한다. 만료·동의 철회 때에는 재로그인/재동의를 안내한다.

### `/아이템` 명령

```text
/아이템 캐릭터:예시히어로
```

- 명령 이름은 `아이템`, 필수 옵션은 문자열 `캐릭터`다. UI 세션에서 별도로 닉네임을 다시 입력하게 하지 않는다.
- 닉네임 → OCID → 기본 정보·스탯·장비를 조회하고 그 캐릭터의 직업·월드·현재 장비를 기준으로 검색한다. 기본/장비 데이터의 시점을 표시한다.
- 계정을 연결했다면 내 캐릭터 목록 autocomplete를 제공할 수 있다. 연결하지 않았어도 공개 닉네임 조회는 가능하다.
- 닉네임 조회 성공만으로 `내 캐릭터`라고 표시하지 않는다. 다른 캐릭터도 공개 범위 안에서 비교할 수 있다.
- 캐릭터가 없거나 데이터가 부족하면 원인을 표시한다. 대표 캐릭터나 이전 요청 캐릭터로 조용히 대체하지 않는다.
- `/메이플`은 감시·연결 관리 허브로 둘 수 있으나 아이템 검색의 기본 진입은 `/아이템 캐릭터:...`다.

## 4. 아이템 선택·가격 범위

```text
매물 검색                       [본인에게만 표시]
캐릭터: 예시히어로 · 월드: 스카니아
공개 캐릭터 조회: 서비스 키 / 넥슨 계정 연결: 선택 / 경매장: 별도 상태

[ 부위: 장갑                              ▼ ]
[ 아이템 여러 개 선택 · 현재 3개 선택      ▼ ]
[해당 부위 전체 선택] [선택 해제]

기준 예산: 30억 메소
검색 범위: 21억 ~ 39억 메소 (±30%)

[예산 변경] [추가 조건] [매물 검색]
[감시 목록] [계정 연결 관리]
```

- **기준 예산 30억은 지출 상한 30억이 아니다.** 사용자가 요청한 ±30%를 적용하므로 39억까지 검색·알림 대상이 된다. `기준 예산 초과 제외`를 추가로 켜면 21~30억으로 줄이고 화면에 바뀐 범위를 표시한다.
- 경계는 메소 정수로 계산한다. `최소=ceil(0.7×B)`, `최대=floor(1.3×B)`이며 포함 경계다. 음수·0·오버플로를 거절한다.
- 아이템 ID 집합 안에서는 OR, 예산·월드·부위·추가 스펙 조건끼리는 AND다.
- 이름 부분 일치 대신 제공자 카탈로그의 정규 ID/변형 ID를 사용한다. 카탈로그는 캐릭터 API가 자동 제공한다고 가정하지 않는다.
- String Select 한 번에 최대 25개를 표시하되, 다음 페이지의 선택도 유지한다. `전체 선택`은 현재 보이는 25개가 아니라 **해당 필터에 맞는 카탈로그 전체**를 뜻한다. 전체 선택 시점의 카탈로그 버전과 ID 집합을 고정한다.
- 실제 요청은 제공자가 허용하는 아이템 수·페이지 수에 맞춰 분할한다. 부위 변경 시 이전 부위의 선택을 새 부위로 적용하지 않는다.

## 5. 검색·추천 결과

결과가 제공한 옵션·가격·판매 상태로 필터링한다. 가격 수집 시점과 캐릭터 snapshot 시점을 각각 표시한다. 검색 결과가 일부 페이지만 수집된 경우 `전체 검색 완료`라고 표시하지 않는다.

| 결과 유형 | 처리 |
| --- | --- |
| 조건 일치 + 계산 모델 지원 | 현재 장비 100점 기준 개인 교체점수·개선량·1억당 개선량 |
| 조건 일치 + 모델 미지원 | 옵션·가격은 표시, `개인 점수 미지원`. 임의 점수 부여 안 함 |
| 예산·스펙 조건 불일치 | 기본 결과에서 제외, 제외 이유는 요약 가능 |
| 판매 종료·상태 확인 불가 | 상태 표시. 알림 직전 재확인 가능한 경우 재확인 |
| 제공자 인증·한도·연결 문제 | 재연결/대기 안내. 빈 결과와 조회 실패를 구분 |

검색은 사용자가 고른 모든 아이템을 대상으로 한다. 첫 개인 계산 모델은 앞선 예제의 히어로·동일 기본 조건 장갑이며, 지원하지 않는 아이템도 검색 자체를 막지는 않는다. 개인 점수 알림은 해당 모델의 지원 후보에만 적용하고, 나머지는 명시적으로 `스펙 조건 알림`을 선택할 수 있다.

## 6. 기간 알림 설정

검색 결과의 `알림 설정` 버튼이 Modal을 연다. 체크박스 지원을 위해 JDA 6.7.0 업그레이드를 계획한다. 기간은 하나만 선택해야 하므로 체크박스와 별도로 단일 선택을 사용한다.

```text
매물 알림 설정

☑ 기간 알림 사용
기간: ○ 1일  ● 3일  ○ 7일
최소 모델 성능 상승: 4%
최소 가성비: 0.18점/억
알림 이벤트: ☑ 새로 발견한 매물  ☐ 가격 하락

수신: Discord DM + 개인 수신함
확인 주기: 30분 (제공자 한도·오류 시 지연 가능)
현재 검색 범위: 21~39억 / 선택한 장갑 3종
                    [취소] [제출]
```

상기 Modal은 Checkbox, RadioGroup, TextInput 2개, CheckboxGroup의 **최상위 Label 5개**로 구성한다. 스펙 조건만 사용하는 모드에서는 점수 입력 대신 현재 스펙 조건을 요약하고 개인 점수를 약속하지 않는다.

시작 전에는 실제 적용된 검색 범위, 선택 아이템 수, 조건, 감시 종료 시점(KST), DM 수신 상태, 예상 확인 주기를 요약한다. 사용자의 `감시 시작` 버튼으로 활성화한다. 체크하지 않으면 일회성 검색만 한다.

### 좋은 매물의 정의

```text
공통 필수 조건
= 올바른 월드·부위·선택 아이템
  AND 21억 ≤ 가격 ≤ 39억
  AND 추가 스펙 필터 만족
  AND 판매 상태 적합

개인 점수 모드
= 공통 조건 AND 모델 지원
  AND 개선율 ≥ 4% AND 개선점수/가격(억) ≥ 0.18

스펙 조건 모드
= 공통 조건
```

임계값은 사용자가 설정한다. `좋은 매물`을 AI의 자유 판단으로 결정하지 않는다. AI가 붙는다면 검증된 숫자의 설명만 보조한다.

### 구체적인 알림 예

기준 예산 30억, 선택한 장갑, 크뎀 16% 이상, 개인 모델 개선율 4% 이상, 가성비 0.18점/억 이상, 기간 3일로 감시한다.

- 기존 C: 38억, 점수 105.160302, 가성비 약 0.135797점/억. 가성비 조건 미달.
- 새로 발견한 D: 같은 비교 옵션에 25억. 점수 105.160302, 모델 개선 약 5.16%, 가성비 약 0.206412점/억. 조건 충족.

```text
[Discord DM · som-bot]
설정한 조건에 맞는 장갑을 발견했어요.
가격 25억 · 검색 범위 21~39억
크뎀 16% · STR 9%
교체점수 105.16 · 모델 성능 +5.16%
가성비 0.206점/억 · 감시 종료까지 2일 18시간
처음 확인한 시각: 14:05 KST

[매물 원본 보기] [감시 일시정지] [알림 관리]
```

이는 가상 예다. 제공자가 등록 시각을 주지 않으면 `방금 등록`이 아니라 `처음 확인`이라고 표현한다. 첫 감시 조회에서 이미 존재한 매물을 새 매물로 일괄 알림하지 않는다. 같은 매물을 다시 조회해도 새 알림을 보내지 않는다.

가격 하락을 선택한 경우는 같은 매물이라도 마지막 통지 가격 대비 유의미한 하락 조건(초기 제품 정책: 10% 이상)과 원래 조건을 만족하면 별도 이벤트로 알린다. 이 비율은 경매장 제공자의 사실이 아니라 제품 정책이다.

## 7. 감시 운영·실패 UX

- UI 세션(마지막 조작 뒤 10분)과 감시 기간은 독립적이다. Discord를 닫아도 **서버 조회가 허용된 제공자 연결이 살아 있으면** 기간까지 감시한다.
- 기본 확인 주기는 사용자 요청에 따라 **30분**으로 한다. 제공자 최소 간격·키/계정/앱 한도에 따라 더 길어질 수 있다. 실제 주기와 마지막 정상 조회를 표시하며 실시간·누락 없음으로 홍보하지 않는다.
- 정기 조회는 하루 48회다. 매번 검색을 생성한다면 검색 조건 1개는 48회, 2개는 96회, 3개는 144회를 사용한다. 최초 기준선·수동 검색·시세 조회·재시도 비용도 합산해 실제 잔여량을 확인하고, 한도가 부족하면 간격 연장 또는 `한도 대기`를 안내한다.
- 브라우저 연결형 제공자라면 브라우저가 꺼지거나 세션이 만료되면 `연결 끊김` 상태다. 이 경로를 서버 단독 24시간 감시라고 표시하지 않는다.
- 상태는 `준비 중 / 감시 중 / 일시정지 / 인증 필요 / 한도 대기 / 오류 / 만료 / 종료`로 구분한다.
- 종료 시각이 지나거나 사용자가 중지하면 이후 발송 직전에도 상태를 다시 검사해 알림을 막는다.
- 개인 토큰 갱신은 grant version을 구분한다. 연결 해제는 해당 grant가 필요한 감시·미발송 알림을 중지한다. 서비스 키의 공개 캐릭터 조회만 사용하는 감시와 경매장 인증은 별도 의존성을 관리한다.
- DM이 막혀 있으면 개인 수신함에 남기고 `/메이플`에서 안내한다. 사용자 동의 없이 서버 채널로 대신 보내지 않는다.
- 캐릭터 기준 snapshot은 감시 시작 시 고정한다. 갱신은 명시적으로 재평가·조건 버전을 올려 적용하고 새 기준선을 만든다.

## 8. 구현 순서·출시 기준

| 순서 | 구현 범위 | 확인할 결과 |
| --- | --- | --- |
| 0 | Open ID 프렌즈/검수·경매장 제공자 확인 | Open ID client/scopes/승인, 경매장 별도 인증·서버 검색/주기 조회 권한 |
| 1 | 웹 포털·Discord/Nexon OAuth·암호화 토큰 매핑 | 다른 계정 링크 거절, UID·scope 확인, 갱신 회전·철회·재동의 |
| 2 | `/아이템 캐릭터`·JDA 6.7.0·아이템 선택 | OCID 고정, 개인 키 없이 공개 조회, 전체 선택·±30% 경계·기존 봇 회귀 |
| 3 | 카탈로그/경매장 어댑터·정규화·평가 | 부분 조회 표시, 미지원 모델 구분, 숫자 fixture 재현 |
| 4 | 기간 감시·기준선·중복 처리·Outbox | 재시작·중복 실행·조건 수정·만료·해제에도 논리적 중복 억제 |
| 5 | DM·개인 수신함·운영 지표 | 차단·429·네트워크 불확실 상태 처리, 공개 채널 유출 없음 |

외부 제공자 계약이 미확정이어도 1~5의 내부 구조·fixture 검증을 진행할 수 있다. 단, 실제 Open ID 인증·동의 대상 호출·경매장 상시 감시는 필요한 승인·제공 조건이 확인된 범위로 제한한다. 사용자에게 다시 사진을 제출하는 방식으로 요구를 바꾸지 않는다.
