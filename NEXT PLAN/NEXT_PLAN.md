# 다음 구현 계획

개인 도구의 실증 단계는 아래 P0~P4로 관리한다. 다만 사용자가 다시 확인한 최종 목표는 **여러 사용자가 한 번 계정을 연결하면 서비스가 후속 작업을 처리하는 흐름**이다. 개인 도구의 원격 화면 조작을 제품 온보딩으로 확장하지 않는다.

## 사용자 재확인에 따른 우선 과제

기존 V3의 일반 사용자 개인 키 필수 입력 제외 원칙을 유지한다. noVNC와 수동 연결 버튼을 줄인 것만으로 다중 사용자 서비스가 완성됐다고 보지 않는다.

| 사용자에게 보이는 흐름 | 서비스가 처리할 일 | 현재 상태 |
| --- | --- | --- |
| 연결 링크에서 공식 로그인·필요한 OTP/동의 | 사용자 신원에 결합한 연결 생성, 사용자별 세션 분리 | Open ID 승인/경매장 위임 범위 미확인. 다중 사용자 구현 없음 |
| 명령의 캐릭터 또는 저장한 기본 캐릭터 사용 | 캐릭터·공개 장비 자동 조회. 일반 사용자 키 입력 없음 | 공개 조회용 운영자 서비스 키 설계는 V3에 있음. 개인 프로토타입과 미통합 |
| 예산·원하는 아이템·감시 기간 지정 | 실제 매물 검색·계산·주기 감시·알림·기준선 저장 | 단일 사용자 프로토타입 일부 구현. 사용자별 DB/알림/재시작 복원 미구현 |
| 제공자가 요구할 때 재인증 | 해당 사용자의 작업만 중지하고 연결 복구 상태 안내 | 단일 사용자 인증 무효화는 구현. 실제 세션 수명과 다중 사용자 격리 미검증 |

다음 구현 전에 경매장 연결의 실제 전달 방법을 검증한다. [공식 게임 데이터 활용 로그인](https://openapi.nexon.com/ko/data-util/introduction/)은 지정된 프렌즈 제공 기능이며, 계정 연결 승인이 경매장 검색 권한까지 포함한다는 근거는 아직 없다. 현재 브라우저 세션 방식을 택하면 사용자별 독립 프로필·접근 제어·연결 화면이 필요하다. 비밀번호만 받아 영구 무인 운영이 가능하다고 약속하지 않는다.

완료 조건은 두 사용자 동시 연결에서 캐릭터·검색 한도·결과·감시가 섞이지 않고, 일반 사용자가 API 키 발급/noVNC 비밀번호/앱 연결 버튼/매회 캐릭터 선택을 수행하지 않아도 되는 것이다. 최초 대상이 불명확할 때만 기본 캐릭터를 한 번 정하며 임의 캐릭터를 대신 선택하지 않는다. 공식 로그인·OTP·동의는 제공자 절차가 요구하는 경우 남는다.

## 개인 계정 실증 단계

| 단계 | 할 일 | 완료 조건 |
| --- | --- | --- |
| P0 · 로컬 실행 | 인수인계 브랜치 받기, Docker Desktop 실행, noVNC 접속, 수동 로그인/OTP | 앱·브라우저 health 정상, 본인 계정에서 에반이였솜 조회. 가상 데이터로 대체하지 않음 |
| P1 · 실제 검색 호환성 | 본인 월드·부위·가격·옵션으로 소수 회 조회, 공식 화면과 대조 | 실제 매물의 ID·가격·옵션·판매 상태 일치, 잔여 검색량 확인. 오류 시 근거를 남겨 필요한 어댑터만 수정 |
| P2 · 계산 정합성 | 최신 캐릭터 snapshot과 착용 장비, 에반 마력 축, 매물 교체 비교 확인 | 동일 장비 0% 등 기준 검사와 실제 장비 대조, 미지원 옵션 명시. 환산 템환산과 동일하다고 표시하지 않음 |
| P3 · 30분 실관측 | 조건 하나로 실제 30분 이상 조회, 기준선·신규 판정·중복·한도 확인 | 실제 회차 시각/한도/결과 기록. 신규 매물이 없으면 조회 성공만 확인했다고 기록 |
| P4 · 장시간·복원 | 세션 만료/계정 변경/절전/재시작 관측, 필요 시 감시·기준선 저장 설계 | 실제 세션 수명 관측, 계정이 맞을 때만 복원. API 키 저장·암호화 방식은 별도 설계 후 구현 |
| P5 · Discord 통합 | 기존 V3 명세 재검토, 제공자 권한 확인, 별도 모듈/명령/알림 구현 | 닉네임 기준 검색 패널·부위/아이템 다중 선택·예산 ±30%·기간 감시·개인 DM과 오류 수신함을 검증 |

## P0~P3에서 남길 산출물

- `VALIDATION.md`: 커밋·Windows/Docker/브라우저 버전·실제 로그인 성공 여부·검색/계산/감시 결과.
- 버그 수정이 있으면 변경 이유와 공식 문서/공개 코드의 근거, 관련 테스트.
- 실제 API와 fixture가 다른 필드는 값의 비밀을 제거하고 스키마 차이만 기록.
- 외부 권한·세션 정책이 불명확하면 확인할 항목과 운영 범위에 주는 영향을 명시.

## P5에서 다시 확정할 기능

- `/아이템 캐릭터:닉네임`으로 기준 캐릭터 조회와 본인에게만 보이는 조작 패널.
- 부위·아이템 여러 개/전체 선택, 예산 70~130%, 추가 옵션 입력.
- 기간 선택 후 30분 감시, 신규 조건 충족 매물만 개인 DM. DM 차단 시 수신함 처리.
- `/api`는 외부 웹 계정 연결 흐름. 현재 개인 프로토타입의 메모리 키 입력을 다중 사용자 계정 연결 완료로 취급하지 않음.
- 공개 조회 서비스 키·사용자 grant·경매장 브라우저 세션을 별도 권한으로 관리.

이 단계에서 기존 PostgreSQL·RabbitMQ·Redis·gateway/worker 구조와 [기술 명세 V3](../docs/internal/analysis/MAPLE_MARKET_TECH_SPEC_2026-10-23.md)를 함께 검토한다. 현재의 개인용 브라우저 프로필 한 개를 여러 Discord 사용자가 공유하는 구조로 확장하지 않는다.

## 실행 결과 보고 형식

```text
환경/커밋:
실행·로그인·캐릭터 조회:
실제 매물 검색·잔여 한도:
장비 교체 계산 대조:
30분 감시 실제 관측:
가상 테스트 결과:
수정 사항/참고 근거:
남은 문제와 다음 단계:
```

실제 로그인·OTP·API 키 입력은 사용자가 공식/로컬 화면에서 수행한다. 그 외 코드 확인·설치·빌드·실행·수정·테스트는 가능한 범위에서 이어서 진행한다. `main` push는 운영 배포를 일으키므로 검증 작업의 저장은 작업 브랜치에서 한다.
