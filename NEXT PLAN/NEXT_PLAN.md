## P0 · 실제 계정으로 로컬 연결

1. `next-plan/maple-local-handoff` 브랜치를 Windows 로컬에 받는다.
2. Docker Desktop을 Linux 컨테이너 모드로 실행한다.
3. 프로토타입을 빌드하고 noVNC 화면에 접속한다.
4. 공식 경매장 탭에서 사용자가 직접 로그인·OTP를 완료한다.
5. 인증된 계정의 캐릭터 목록에서 `에반이였솜`을 선택한다.

로그인 화면이 열렸다는 것만으로 완료 처리하지 않는다. 실제 캐릭터 응답이 확인되어야 한다.

## P1~P3 · 실제 검색·계산·감시

- 실제 검색은 좁은 조건으로 소수 회만 실행하고 공식 화면과 대조한다.
- 검색량, 응답 코드, 내부 클라이언트 버전을 기록하되 쿠키·키·전체 서명 URL은 남기지 않는다.
- 장비 비교는 단순 옵션부터 수동 계산과 대조한다. 환산주스탯 템환산과 동일하다고 표시하지 않는다.
- 감시는 전체 결과가 한 페이지에 들어오는 조건 하나로 시작한다.
- 새 매물이 없으면 “정기 조회 성공·신규 0건”으로 기록한다. 알림 성공으로 바꾸어 쓰지 않는다.

## P4 · 개인용 장기 실행과 복원

P0~P3가 통과하면 다음 데이터를 영구 저장한다.

- 선택한 계정·캐릭터의 내부 참조와 확인 시각
- 감시 조건, 시작·종료·다음 실행 시각
- 기준선과 이미 알린 매물의 최소 식별 정보
- 감시 오류와 마지막 성공 회차
- 로컬 알림 수신함

API 키와 로그인 세션을 저장하기 전에는 암호화 키 관리, 삭제 범위, 백업 포함 보관 기간을 먼저 설계한다. 재시작 뒤에는 계정이 같은지 확인한 경우에만 감시를 복원한다.

## P5 · DIS 검색과 알림 연결

다음 기능을 다시 확정한다.

- `/메이플 연결`: 본인에게만 보이는 응답에서 별도 웹 연결 화면으로 이동
- `/아이템 캐릭터:닉네임`: 기준 캐릭터를 정하고 조작 화면 생성
- 부위·아이템 다중 선택, 전체 선택, 예산 70~130%, 추가 옵션 입력
- 점수순·가성비순·가격순 정렬과 추천 이유 표시
- 기간 1/3/7일, 30분 감시, 신규 조건 충족 매물만 개인 DM
- DM 차단·세션 만료·검색 실패를 확인할 개인 수신함
- 감시 목록 조회, 일시정지, 재개, 삭제

현재 프로토타입의 메모리 API 키 입력을 다중 사용자 계정 연결 완료로 취급하지 않는다. 공개 조회용 API 키, 사용자 grant, 경매장 브라우저 세션은 별도 권한으로 관리한다. 개인 브라우저 프로필 한 개를 여러 Discord 사용자가 공유하지 않는다.

기존 PostgreSQL·RabbitMQ·Redis·gateway/worker 구조와 [기술 명세 V3](../docs/internal/analysis/MAPLE_MARKET_TECH_SPEC_2026-10-23.md)를 실제 관측 결과에 맞춰 다시 검토한다. 처음부터 모든 구성요소를 별도 서비스로 만들지 않고, 브라우저 세션 실행기처럼 격리가 필요한 경계부터 분리한다.

## P6 · 추천 품질 개선

- 직업·부위별 지원 옵션과 미지원 옵션을 목록으로 관리한다.
- 수동으로 확인한 장비 교체 사례를 평가 데이터로 남긴다.
- 현재 페이지 순위뿐 아니라 같은 조건의 가격 분포와 유사 매물을 비교한다.
- 개선율, 가격, 가성비, 필터 통과·탈락 이유를 규칙 기반으로 먼저 제공한다.
- AI를 붙일 경우 검증된 상위 후보의 차이를 설명하고 사용자의 추가 질문에 답하는 역할로 제한한다.

추천 결과는 자동 구매 판단이 아니다. 계산하지 못한 변수를 숨기거나 임의 점수로 채우지 않는다.

## P7 · 여러 사용자에게 공개

- 사용자별 브라우저 세션과 저장 데이터를 격리한다.
- 연결 정보 암호화, 키 교체, 관리자 접근 감사, 연결 해제와 탈퇴 삭제를 구현한다.
- 사용자별 감시 개수와 일일 검색량을 제한한다.
- 동시 검색·감시 부하 테스트로 브라우저와 작업 큐 수용량을 측정한다.
- 검색 실패율, 정기 감시 지연, 중복 알림, 세션 만료, DM 실패를 지표로 남긴다.
- 제공자 오류가 늘면 자동 호출을 줄이는 차단 장치를 둔다.

## 실행 결과 보고 형식

```text
환경/커밋:
실행·로그인·캐릭터 조회:
실제 매물 검색·잔여 한도:
장비 교체 계산 대조:
30분 감시 실제 관측:
가상 테스트 결과:
수정 사항/참고 근거:
남은 문제와 다음 단계:
```

실제 로그인·OTP·API 키 입력은 사용자가 공식 또는 로컬 화면에서 수행한다. 그 외 코드 확인·설치·빌드·실행·수정·테스트는 가능한 범위에서 이어서 진행한다. `main` push는 운영 배포를 일으키므로 검증 결과는 작업 브랜치에 저장한다.
