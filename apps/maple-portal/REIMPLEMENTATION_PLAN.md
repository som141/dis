# 메이플 경매장 재구현 계획 — 검토안

작성: 2026-11-04 / 대상: 로컬 Docker 포털 / 당시 검토안

후속 결정: 아래의 솔 에르다 조각 전용 시세 기능은 종료했다. 현재 포털 기능은 [사용 안내](PORTAL.md)를 따른다.

이 문서는 다음 구현의 요구사항·데이터 확보 방법·완료 기준을 정한다. 이번 작업은 조사와 계획서 작성까지다. 프로그램 코드, 실행 중인 컨테이너, 저장된 감시 조건을 변경하지 않는다. 사용자가 계획을 확인한 뒤 구현한다.

## 1. 확인한 현재 문제

| 항목 | 코드에서 확인한 상태 | 다음 구현의 기준 |
| --- | --- | --- |
| 아이템 이름 | `public/portal.js`의 이름 후보는 내 캐릭터의 착용 장비 목록에서 생성 | 전체 장비 카탈로그를 별도로 갖추고 부위·직업군에 따라 선택지 제공 |
| 잠재 옵션 | `src/domain.mjs`가 10개 키 중 한 옵션과 합산 최소값만 처리 | 일반 잠재·에디 각각 여러 조건, 장비별 유효 옵션과 수치 제공 |
| 에디셔널 | 등급만 검색에 전달하고 옵션 조건은 받지 않음 | 에디 전용 옵션 선택·수치·검색 매핑 구현 |
| 예산 | 상한 또는 기준값의 ±30%로 고정 | 최소·최대 직접 입력, 상한만, 사용자 지정 비율, 제한 없음 |
| 감시 OFF | 최초 실행에는 조건 분기가 있지만 저장된 감시·복원·화면 변경까지 일관된 보장이 부족 | OFF 상태의 작업에는 예약 조회가 존재하지 않도록 상태와 저장 구조 정리 |
| 솔 에르다 조각 | 별도 화면·전용 검색 조건 없음 | 재화 시세 전용 탭 추가 |
| 화면 | 긴 입력 행과 일반적인 패널 중심 | 사용자가 선택한 **메이플 분위기의 아이템 도감**으로 재설계 |

감시 OFF의 실제 오작동 원인은 아직 재현 검증하지 않았다. 기존 조건문이 없다고 단정하지 않고, 재현 조건과 저장·예약 경로를 함께 점검한다. 현재 버전의 테스트 통과를 이번 조사 결과로 주장하지 않는다.

## 2. 먼저 확보해야 할 데이터

### 2.1 장비 카탈로그

대상은 **한국 메이플스토리의 일반 능력치 장비 전체**다. 무기·보조무기·엠블렘·방어구·장신구·기계심장 등 현재 분류를 전수 대조한다. 캐시 코디는 이번 능력치 장비 도감과 별도 범위로 둔다. 거래 불가 장비도 도감에 구분해 보관하고, 경매장 검색 가능 필터를 기본 적용한다. 거래 가능 여부를 확인하지 못한 항목을 임의로 숨기거나 거래 가능으로 확정하지 않는다.

| 데이터 | 필요한 필드 | 확인 방법 |
| --- | --- | --- |
| 아이템 식별 | KMS 아이템 ID, 정확한 한글 이름, 동명 구분, 별칭 | 원본 식별자와 이름 대조; 이름만으로 합치지 않음 |
| 착용 조건 | 부위·세부 종류, 직업군/공용, 개별 직업 제한, 요구 레벨 | 직업 비트/제한을 정규화; 공용 장비의 중복·누락 검사 |
| 표시 정보 | 아이콘, 세트/계열, 기본 능력치 | 출처와 버전을 기록; 아이콘이 없어도 이름 선택은 가능 |
| 강화·거래 | 잠재/에디 부여 가능 여부, 거래 속성, 경매장 지원 분류 | 장비 예외 및 장비별 거래 상태를 구분 |
| 갱신 정보 | 원본 지역·게임 버전, 확인일, 원본 URL/해시, 보완 이력 | 신장비·이름 변경·분류 변경을 버전별 비교 |

확보 순서는 다음과 같다.

1. 공식 웹 경매장이 사용하는 아이템 이름/분류 자료와 공식 공개 정적 자료에서 전체 목록을 얻을 수 있는지 확인한다. 카탈로그를 만들기 위해 실시간 매물 검색을 아이템마다 실행하지 않는다.
2. 공식 자료만으로 부족하면 KMS 버전과 사용 조건을 확인할 수 있는 공개 데이터 원본을 조사한다. GMS·MSEA 등 다른 지역 데이터를 그대로 사용하지 않는다. 채택할 원본과 버전, 부족한 필드를 기록한다.
3. 원본을 공통 스키마로 변환하고 공식 아이템 정보·업데이트·실제 응답 표본으로 대조한다. 내 착용 장비와 현재 판매 중인 매물은 검증 자료이며 전체 목록의 대체물이 아니다.
4. 부위별·직업군별 항목 수, 필수 필드 누락, 동명 항목, 미분류·신규 장비 목록을 보고한다. 전체 원본과 대조가 끝나기 전에는 전체 장비 지원 완료로 표시하지 않는다.

**현재 확보 상태:** 완전한 장비 원본은 아직 확보하지 못했다. 2026-11-04에 확인한 Nexon Open API 공개 명세에서는 전체 장비 사전 경로를 찾지 못했다. 웹 경매장의 직접 HTTP 접근은 보안 검사에 막혀 이번 조사에서 카탈로그 원본을 확인하지 못했다. 이 부분은 구현 첫 단계의 데이터 의존성으로 남긴다.

### 2.2 일반 잠재·에디셔널 규칙

옵션명 목록을 늘리는 것만으로는 완료가 아니다. 다음 기준을 결합한 규칙표를 만든다.

| 구분 | 보관할 내용 |
| --- | --- |
| 적용 조건 | 일반 잠재/에디, 부위·특수 장비 종류, 요구 레벨 구간, 장비 등급, 옵션 줄의 등급 |
| 옵션 | 원문·정규화 이름, 공식 검색 키, 단위(%·초·고정값·레벨당 수치·스킬 유무), 가능한 실제 값 |
| 줄 규칙 | 첫 줄/나머지 줄의 등급 범위, 중복 가능 여부, 함께 성립할 수 있는 조건 |
| 예외 | 무기·보조·엠블렘 차이, 포스실드·소울링, 모자·장갑·장신구 등 부위별 특수 옵션 |
| 이력 | 현재 재설정 가능 옵션과 기존 매물에 남은 과거 옵션의 차이, 근거 버전·확인일 |
| 검색 지원 | 서버에서 직접 가능한 조건, 결과를 받은 뒤 확인해야 하는 조건, 아직 미확인인 조건 |

일반 잠재는 공식 [잠재능력 재설정 표](https://maplestory.nexon.com/Guide/OtherProbability/cube/black), 에디는 공식 [에디셔널 재설정 표](https://maplestory.nexon.com/Guide/OtherProbability/cube/addi)를 기준으로 수집·대조한다. 두 페이지는 부위·등급·레벨을 입력하는 구조이고 줄별 옵션 등급도 안내한다. 레전드리 장비의 모든 줄을 레전드리 수치로 취급하지 않는다.

공식 페이지의 공개 스크립트에서 확률표 조회 방식은 확인했으나, 이번 직접 표 조회는 정상 옵션표 대신 다른 페이지로 이동했다. 따라서 **실제 옵션 수치표의 전수 확보는 아직 미완료**다. 공식 화면에서 확인 가능한 표를 기준으로 수집 경로와 레벨 경계값을 검증한다. 2021년 안내나 기억에 의존한 수치를 현재 규칙으로 고정하지 않는다.

## 3. 검색·감시 동작

### 3.1 감시 OFF = 한 번 조회

- 기본값은 OFF, 실행 버튼은 `한 번 조회`로 표시한다. ON이면 `조회 후 감시 시작`으로 바뀐다.
- 한 번 조회는 선택한 조건을 한 차례 실행하고 필요한 결과 페이지를 수집한 뒤 종료하는 뜻이다. 여러 페이지를 가져오는 HTTP 요청과 주기 재검색은 구분한다.
- OFF 작업은 로그인 완료·새로고침·컨테이너 재시작·세션 재연결 때 자동 재검색하지 않는다.
- 이미 감시 중인 항목에서 OFF를 선택하면 해당 항목의 예약을 즉시 해제하고 서버 저장 완료 상태를 보여준다. 다른 항목의 감시는 계속된다.
- 이미 전송한 요청은 취소 시도를 하고, 응답이 늦게 도착해도 다음 조회를 예약하지 않는다. 이미 소비한 검색 횟수는 복구되는 것으로 표시하지 않는다.
- 일반 검색 조건 변경은 검색 버튼을 눌러 적용한다. 감시 OFF와 `감시 중지`는 즉시 적용한다. ON으로 바꾸기만 해서는 감시를 시작하지 않는다.
- 감시 설정과 실행 상태를 한 작업 ID에 연결하고, 복원·예약 실행 직전에 모두 ON 여부를 확인한다. 이전 버전에서 상태가 모호한 작업은 사용자 확인 대기로 옮긴다.

### 3.2 장비 선택 순서

`부위 → 직업군(전체/전사/마법사/궁수/도적/해적) → 아이템 이름 → 강화·잠재 → 예산 → 실행`

- `모자 + 마법사`는 마법사 착용 가능 모자와 공용 모자를, `모자 + 전체`는 모든 직업군의 모자를 보여준다.
- 내 캐릭터의 직업군을 초기 선택으로 제안하되 전체 전환을 제공한다. 직업군과 개별 직업 전용 제한은 별도 정보로 처리한다.
- 이름 선택은 검색 가능한 도감 목록으로 제공한다. 각 선택지에 아이콘·정확한 이름·요구 레벨·직업군을 표시하고 이름 일부/초성 검색을 지원한다.
- `이 부위 전체 검색`을 별도 선택지로 제공한다. 이는 분류·직업군 조건 검색이며, 모든 아이템 이름을 각각 조회하는 작업으로 변환하지 않는다.
- 특정 아이템 여러 개 선택은 검색 목록에 태그로 추가한다. 이름 OR 검색이 제공된다고 가정하지 않고 실제 생성될 검색 수를 실행 전에 표시한다.
- 상위 조건을 바꿔 선택 장비나 옵션이 맞지 않게 되면 잘못된 항목을 표시하고 재선택을 요구한다. 아이템 이름과 부위가 어긋난 검색을 조용히 전송하지 않는다.
- 아이템 ID는 로컬 식별에 사용한다. 경매장에 ID 검색이 지원되는지는 별도 검증하고, 현재 확인된 이름·정확 일치·분류 매핑을 기본으로 둔다.

### 3.3 잠재·에디 조건 입력

- 일반 잠재와 에디를 독립 영역으로 분리한다. 등급은 `무관 / 없음 / 레어 / 에픽 / 유니크 / 레전드리`로 구분해 `없음`과 `무관`의 혼동을 없앤다.
- 장비·요구 레벨·선택 등급에 맞는 모든 옵션을 제공한다. 내 직업 추천 옵션은 위에 둘 수 있지만 다른 유효 옵션을 숨기지 않는다.
- 여러 조건을 추가·삭제할 수 있게 하고, 옵션별 단위를 표시한다. 고정값과 %, 일반 잠재와 에디를 섞지 않는다.
- `같은 옵션의 합산 최소값`과 `줄별 조건 충족`을 명확하게 구분한다. 줄별 값은 실제 가능한 값에서 고르고, 합산 최소값은 가능한 합계 범위를 안내한다.
- 검색의 줄별 조건 충족과 게임의 첫째/둘째/셋째 줄 위치 지정은 다르다. 위치 지정·정확값·최대값은 제공자가 지원하는지 확인한 범위에서만 제공한다.
- 여러 아이템의 레벨·부위가 다르면 아이템별로 유효성을 검사한다. 전체 부위 검색에서도 후보 장비별 허용 값의 합집합과 각 장비 적용 여부를 처리한다.
- 서버 검색이 지원하지 않는 유효 옵션은 결과의 원문으로 판별 가능한지 확인한다. 후처리가 필요하면 적용 범위와 부분 수집 여부를 표시하고, 판별할 수 없는 조건을 적용 완료로 표시하지 않는다.
- 과거 매물에 존재할 수 있는 옵션을 현재 재설정 표에 없다는 이유만으로 오염 데이터로 삭제하지 않는다. 현재/과거 옵션 근거를 분리한다.

### 3.4 예산

- 기본은 기존 요청대로 `200억 이하`다.
- `최소~최대 직접 지정`을 제공한다. 예: `120억 ~ 200억`. 양쪽 입력과 범위 슬라이더를 동기화하고 입력으로 슬라이더 범위를 확장할 수 있게 한다.
- `기준 예산 ±비율`도 비율을 직접 바꿀 수 있게 한다. 30%는 빠른 선택 중 하나다.
- 하한·상한 개별 해제와 `가격 제한 없음`을 지원한다. 적용될 메소 금액을 함께 보여준다.
- 억·만 단위 입력을 정수 메소로 변환하고 소수·경계값·최소값 초과·저장 후 복원까지 검증한다.

## 4. 솔 에르다 조각 전용 시세

상단에 `장비 도감 · 매물`과 별개의 `솔 에르다 조각` 탭을 둔다.

- 거래 가능한 정확한 아이템을 확인해 전용 검색 조건으로 고정한다. 이벤트 교환 불가 조각·교환권·솔 에르다 본체와 구분한다.
- 현재 판매 중인 매물은 개당 최저가·가격대·등록 수량, 판매 완료 자료는 날짜별 개당 중앙값·사분위 상자그림·거래 건수·확인 가능한 거래 수량을 보여준다.
- 기본 기간은 KST 오늘을 포함한 최근 14일이다. 오늘은 진행 중인 날짜로 표시하고, 자료가 없는 날을 0원으로 그리지 않는다.
- 통계의 기본 표본은 판매 완료 매물 1건의 개당 가격이다. 거래 건수와 수량을 구분하고, 수량 가중 통계를 추가한다면 별도 지표로 명시한다.
- 현재 호가와 체결가는 각각 표시한다. 재화에는 장비 잠재·스타포스·내 캐릭터 개선율을 적용하지 않는다.
- 월드/거래 범위를 명확히 표시한다. 장비에서 고른 예산이나 잠재 조건이 재화 시세에 섞이지 않게 한다.
- 조회 버튼을 눌러 갱신하고 수집 시각을 보여준다. 탭을 열었다는 이유만으로 새 검색을 생성하지 않는다. 판매 중+판매 완료를 함께 조회할 때 필요한 별도 검색 수를 안내한다.
- 일단 모은 자료와 날짜별 요약을 저장해 재시작 후 조회 가능한 범위를 표시한다. 상세 자료를 보관하지 않았다면 재조회 필요 상태를 분명히 한다.

**14일 완전성 확인:** 공식 안내상 리스트 표시 상한은 검색당 10,000건이고 30,000건 이상이면 조건을 좁혀야 한다. 거래량이 많으면 한 검색으로 14일 자료가 모두 들어오지 않을 수 있다. 날짜별 서버 필터 또는 검증된 분할 수집이 가능한지 먼저 확인한다. 미지원이면 과거 14일 전량 확보를 약속하지 않고, 실제 날짜 범위·일별 누락/상한 도달 상태를 표시한다. 이후 축적은 과거 미수집 거래를 복구하는 것으로 설명하지 않는다. 상한에 걸린 가격순 표본을 전체 시장의 중앙값으로 표시하지 않는다. ## 5. 디자인: 메이플 분위기의 아이템 도감

큰 제목과 입력 행이 화면을 차지하는 구성을 바꾸고 아이템 선택을 중심에 둔다.

| 영역 | 구성 |
| --- | --- |
| 상단 | 작고 명확한 탭, 캐릭터·월드, 연결 상태·검색 잔여량 |
| 왼쪽 | 부위 아이콘 목록, 직업군 탭, 검색 가능한 장비 도감 그리드 |
| 가운데/오른쪽 | 선택한 장비의 게임 툴팁 느낌 카드, 잠재·에디 조건, 예산, 한 번 조회/감시 실행 |
| 결과 | 아이템 아이콘과 주요 옵션을 비교하는 매물 목록, 선택 시 상세 카드, 판매 완료 시세 그래프 |
| 감시 | 현재 감시 항목·주기·다음 조회·중지 상태를 보여주는 접을 수 있는 목록 |
| 재화 탭 | 솔 에르다 조각 아이콘, 개당 가격 요약, 14일 상자그림과 날짜별 표 |

배색은 따뜻한 아이보리·양피지 느낌 바탕, 짙은 갈색 글자, 메이플 주황 포인트로 잡는다. 장비 등급은 색과 텍스트 배지를 함께 사용한다. 픽셀 아이콘은 선명하게 보여주고 본문·가격은 읽기 쉬운 글꼴로 표시한다. 장식·나뭇잎은 가장자리의 작은 요소로 제한해 선택과 수치 비교가 잘 보이게 한다.

도감 목록과 결과는 페이지/가상 목록으로 나눠 대량 장비와 10,000개 매물을 한꺼번에 DOM에 넣지 않는다. 아이콘은 지연 로딩하고 캐시한다. 로그인 영상은 연결이 필요한 동안만 갱신하고, 도감·표·차트를 불필요하게 전체 재생성하지 않는다. 화면 크기가 작으면 도감→조건→결과 순으로 쌓이고 키보드 검색·선택·툴팁 접근을 제공한다.

구현 시 먼저 모자 도감/조건 화면과 솔 조각 시세 화면의 시안을 만든 뒤 같은 디자인으로 나머지 부위를 확장한다. 시안에 예시 데이터를 쓰는 경우 실제 가격·확보된 카탈로그로 오해되지 않게 표시한다.

## 8. 조사 근거와 남은 의존성

- [Nexon Open API 메이플스토리](https://openapi.nexon.com/ko/game/maplestory/) 및 [공개 명세 색인](https://openapi.nexon.com/static/script/specification.json): 2026-11-04 현재 KMS 분류의 한국어 명세 경로를 확인했다. 장착 장비·사용 이력은 전체 장비/가능 옵션 사전과 구분한다.
- [일반 잠재 표](https://maplestory.nexon.com/Guide/OtherProbability/cube/black), [에디셔널 표](https://maplestory.nexon.com/Guide/OtherProbability/cube/addi): 부위·등급·레벨별 옵션 자료의 1차 근거. 표 전체 수치 수집과 최신 레벨 구간 대조는 구현 1단계에서 완료한다.
- [공식 웹 경매장](https://auction.maplestory.nexon.com/): 장비 이름·분류 원본 후보. 이번 직접 접근에서 보안 검사가 나와 실제 카탈로그 제공 여부는 미확인이다.
- [2026-07-23 공식 업데이트](https://maplestory.nexon.com/news/update/808): 30,000건 이상 검색 제한, 리스트 최대 10,000건, 전체 결과 대상 정렬 안내.
- 로컬 코드: `src/domain.mjs`, `src/portal-flow.mjs`, `src/portal-server.mjs`, `public/portal.js`, `vendor/maple-auction/auction/constants.ts`, `vendor/maple-auction/auction/mapping.ts`를 대조했다. vendor의 옵션명·요청 키 목록 자체는 장비별 가능 수치표가 아니다.

계획 확인 시 결정할 내용은 이 범위와 동작 기준이다. 전체 카탈로그와 수치표가 이미 확보됐다는 승인을 요구하는 문서가 아니다. 확인 이후 1단계부터 진행하고, 확보 실패나 요구사항 변경이 필요한 경우 구체적인 차이를 보고한다.
