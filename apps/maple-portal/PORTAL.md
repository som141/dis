# 메이플 마켓 · 검색 / 감시 / 2주 시세

DIS의 정식 Discord 연결은 [메이플 운영 가이드](../../docs/operations/MAPLE_DISCORD_SETUP.md)를 따른다. 아래 `compose.portal.yaml`은 Discord와 PostgreSQL을 쓰지 않는 단독 로컬 체험 모드다. 운영 모드에서는 사용자별 검색·감시·알림 상태를 기존 PostgreSQL의 `maple` 스키마에 저장하고 Chromium 프로필만 볼륨에 둔다.

## 실행

이 폴더에서 Docker Desktop을 켠 뒤 실행한다.

```powershell
docker compose -f compose.portal.yaml up -d --build
```

접속: http://127.0.0.1:18877/

Docker 안에 전용 Chromium이 포함되어 있다. 일반 사용자용 확장 프로그램이나 VNC는 필요 없다. 로그인은 표시된 넥슨 공식 화면에서 직접 수행한다. 네이버 버튼을 선택하면 표시 주소와 제목이 네이버 공식 로그인으로 전환된다.

## 사용 순서

넥슨 공식 로그인 완료 후 계정의 캐릭터 목록에서 조회할 캐릭터를 선택한다. 연결 중에도 같은 목록에서 다른 캐릭터로 바꿀 수 있다. 바꾸면 이전 캐릭터의 감시를 중지하고 검색 조건과 기록을 그 캐릭터의 작업 공간에 보관한다. 다시 선택하면 기록을 복원하며, 감시 재개는 직접 검색을 실행해야 한다. 첫 로그인에서 캐릭터를 자동 선택하지 않는다. 저장된 캐릭터가 있는 재시작에서는 해당 캐릭터를 다시 연결한다.

1. **넥슨 계정 연결**로 로그인·추가 인증을 완료한다. 로그인만으로 새 검색을 실행하지 않는다.
2. **판매 중 매물** 또는 **최근 2주 시세**를 고른다.
3. **아이템 추가**로 필요한 행을 만들고 조회할 행의 선택 체크박스를 켠다. 각 행에 아이템 이름, 부위, 예산을 지정한다. 이름 대신 부위 전체를 선택할 수도 있다.
4. 가격 조건은 **예산 이하 / 예산 ±30% / 제한 없음 / 직접 최소~최대** 중에서 고른다. 기본 예산은 200억이다. 강화·잠재 조건을 펼치면 스타포스, 잠재 등급, 에디셔널 등급, 잠재·에디 합산 최소치와 상한, 이름 일치, 내 월드를 선택할 수 있다. 상한은 경매장 요청이 끝난 뒤 실제 옵션 줄을 확인해 로컬에서 적용한다.
5. 판매 중 매물에서 감시할 행에만 **감시**를 체크한다. 감시 간격(분)과 기간(일)을 정한다. 기간 0은 직접 종료할 때까지다. 화면에서 일일 예상 검색 사용량을 확인할 수 있다.
6. **선택 항목 검색** 또는 **선택 항목 2주 시세 조회**를 누른다. 여러 항목은 순서대로 처리되고 페이지 수집 진행률이 표시된다.
7. 항목별 **결과 보기 / 시세 보기**를 누른다. 판매 중 매물은 가성비, 전투력 증가량, 예상 피해 증가율, 가격으로 정렬한다. 전투력 증가량은 경매장 제공 값이며 예상 피해 증가율과 다른 지표다. 정렬·결과 페이지 이동·CSV 다운로드는 이미 수집한 데이터에 대한 작업이다. 새 검색을 만들지 않는다. **다시 검색 · 1회**는 새 검색을 만든다.
8. **중지**는 현재 조회의 남은 페이지 수집과 다음 감시를 중단한다. **삭제**는 중지 후 해당 작업·설정·기록·보관 표본을 지운다. **완료·중지 기록 삭제**로 종료된 작업만 한꺼번에 지울 수 있다. 이미 보낸 검색 요청은 횟수가 반환되지 않는다.
9. 매물 목록은 아이콘·잠재/에디 등급과 핵심 옵션·가격·스타포스·계산 가능한 개선율을 간단히 표시한다. **자세히 보기**를 누르면 메이플 장비창 형태로 이미지, 실제 스탯과 강화 내역, 일반/에디 잠재, 추가옵션, 거래 조건을 구분한다. 상세를 열 때는 저장된 매물 정보만 사용하며 검색 횟수를 소모하지 않는다. 응답에 없는 능력치는 만들지 않는다.

성능 비교가 필요한 행은 **내 장비 성능 비교**를 켠다. 서버의 공개 API 키를 사용하며 일반 사용자에게 키 입력을 요구하지 않는다. 키 설정이 없을 때 성능 비교를 끄면 매물·시세 조회는 가능하다. 점수는 공개 캐릭터 데이터에 기반한 독립 데미지 모델이며 환산주스탯 템환산이나 전투력 증감 수치가 아니다.

## 조회 범위와 검색 횟수

- 기존 60건/한 페이지 및 단일 감시 제한을 제거했다. 선택한 여러 아이템이 각각 독립된 검색·감시 작업이 된다.
- 검색 생성 POST 뒤에 같은 검색의 페이지를 60건씩 순서대로 GET하여 최대 10,000건을 수집한다. 제공자가 안내한 조회 상한이며, 10,000건을 넘는 결과를 모두 가져온다고 표시하지 않는다.
- GET 오류나 검색 만료 시 자동으로 검색 POST를 다시 만들지 않는다. 부분 결과와 오류를 표시하며 사용자가 직접 다시 조회한다. 처리 중 **중지**를 누르면 진행 중 요청 종료 후 수집을 멈춘다.
- 조회 상한 초과, 중복/누락된 페이지 등은 화면에 표시한다. 10,000건 제한에 걸린 시세는 전체 시장의 대표 통계가 아닌 조회된 표본의 통계다.
- 경매장 서버의 일일 검색 한도와 초기화 정책은 그대로 적용된다. 프로그램에서 한도를 늘리거나 우회하지 않는다. 처음/수동/정기 새 검색이 한도를 사용하며, 같은 검색의 추가 페이지 조회는 새 검색을 만들지 않는다.
- 시세 작업을 실행해도 다른 모드의 기존 판매 중 감시는 유지한다. 같은 모드에서 다시 실행하면 해당 모드의 기존 감시는 새 설정으로 대체되며, 선택에서 제외한 기존 작업은 중지 상태로 남는다.

## 최근 2주 시세와 박스플롯

시세는 판매 완료 검색(`sold`) 결과 중 **실제 판매 완료일 `tradeDate`**이 오늘을 포함한 최근 14일(KST)에 들어오는 거래를 집계한다. 매물 만료일 `endDate`를 거래일로 대신 사용하지 않는다. 오늘의 값은 아직 하루가 끝나지 않은 부분 집계다.

- 표본은 **판매 완료 매물 1건당 1개**이며 개당 메소 가격을 사용한다. 묶음 수량으로 가중하지 않는다.
- 날짜별 거래 수, 최저가, Q1, 중앙값, Q3, 최고가를 제공한다.
- 박스는 Q1~Q3, 박스 안 선은 중앙값, 수염은 1.5×IQR 범위 내 최저·최고가다. 범위 밖 거래는 점으로 표시한다. 점이 많으면 일부만 그리며 실제 이상치 개수는 날짜 상세에서 확인할 수 있다.
- 중앙값 추이 선과 박스플롯을 각각 켜고 끌 수 있다. 로그 눈금도 선택 가능하다. 날짜 위에 마우스를 올리거나 키보드로 선택하면 상세 수치를 표시한다.
- 거래가 없는 날은 통계를 만들거나 선을 이어 그리지 않는다. 거래일 누락·잘못된 가격·기간 밖·판매 완료가 아닌 기록의 제외 건수를 표시한다.
- 날짜별 통계 표와 거래 CSV를 함께 제공한다. 가격/잠재/월드 등 선택한 필터가 시세 표본에도 적용된다.

## 저장과 재시작

방문 브라우저의 HttpOnly 연결 쿠키와 사용자별 Chromium 프로필을 사용한다. 로그인 정보는 Docker의 전용 프로필 볼륨에 남으며, 세션이 만료되면 공식 재로그인이 필요하다. 원본 쿠키를 Node로 추출하거나 다른 사용자에게 복사하지 않는다.

새 화면은 이전 단일 감시 조건을 설정 행으로 옮겨서 보여 주며, 업그레이드만으로 새 검색을 만들지 않는다. 조건과 감시 여부를 확인하고 직접 실행한다.

새 버전의 사용자별 설정, 감시 조건·기준선·다음 조회 시각·수신함, 시세 집계는 체크포인트에 저장한다. 계정이 일치할 때 실행 중 감시를 복원한다. 새 검색 의도는 POST 전에 저장하여 응답이 불확실한 검색을 재시작 직후 반복하지 않는다.

개별 매물·거래의 전체 목록은 실행 중 메모리에 보관한다. 서버 재시작 후에는 저장된 시세 집계는 볼 수 있으나, 개별 거래 목록과 CSV를 다시 얻으려면 직접 재조회해야 한다. 포털 탭을 닫아도 서버의 감시는 계속되며 PC와 Docker를 끄거나 절전하면 멈춘다.

구버전 솔 에르다 조각 작업·표본은 재시작 시 정리한다. 다른 장비 검색 조건, 감시, 14일 시세 기록은 유지한다.

## 운영자 API 키

공개 캐릭터·장비 조회용 키는 `.docker-secrets/nexon-service-key`에 키만 한 줄로 저장한다. 채팅이나 소스 코드에 넣지 않는다. 서버가 약 5초마다 읽으므로 파일 수정 후 재시작은 필요 없다. 경매장 공식 로그인과는 별개의 자격이다.

## 직접 검증할 항목

- [ ] 로그인만 하고 검색을 누르지 않았을 때 새 검색이 생성되지 않는지
- [ ] 서로 다른 아이템과 예산을 여러 행에 넣고, 체크한 행만 실행되는지
- [ ] 예산 이하/±30%/가격 제한 없음 및 강화·잠재·월드 조건이 공식 화면과 일치하는지
- [ ] 60건을 넘는 결과가 여러 페이지에서 수집되는지, 진행률·중지·부분 결과 표시가 맞는지
- [ ] 감시 미선택 행은 한 번만 조회하고, 선택한 행은 설정한 간격으로 감시하는지
- [ ] 시세 조회 중 다른 모드의 기존 감시가 유지되는지
- [ ] 판매 완료일·개당 가격을 CSV와 대조했을 때 14일 범위 및 날짜별 건수가 맞는지
- [ ] 날짜별 중앙값·Q1·Q3와 박스플롯, 거래 없는 날·이상치·로그 눈금이 일치하는지
- [ ] 재시작 후 저장된 시세 집계와 감시 복원이 맞으며, 불확실한 검색을 자동 반복하지 않는지
- [ ] 조회·감시 도중 중지/삭제 후 페이지 수집과 다음 감시가 멈추고, 완료·중지 기록 일괄 삭제가 다른 감시를 유지하는지
- [ ] 자세히 보기의 아이콘·스탯 분해·잠재·에디·추가옵션·거래 조건이 공식 툴팁과 일치하는지

이번 기능 개편의 실계정 검증은 사용자 직접 진행 대상으로 남긴다. 빌드·문법 확인과 실데이터 동작 검증은 구분한다.


## 2026-11-04 검색 오류·옵션 입력 수정

- 장비 도감은 현재 5,756개다. 에테르넬 신발·장갑·망토 15종을 공식 업데이트 749와 공식 자동완성으로 보완했고, 공식 이름 목록의 모든 에테르넬 항목 포함 여부를 검사했다. 전체 최신 장비/거래 속성의 전수 대조까지 완료됐다는 뜻은 아니다.
- 각 행의 ‘이번 검색에 포함’은 여러 검색 행 중 실행할 대상을 고르는 체크박스다. 장비 선택이나 감시 여부와 별개다. 해제한 행은 검증·조회 대상에서 제외된다.
- 일반 잠재와 에디는 각각 ‘최소치 조건 추가’를 눌러 여러 조건을 넣는다. 각 조건은 모든 줄의 합계이며 모든 조건을 동시에 만족해야 한다. 예: 일반 크뎀 15% 이상 + INT 10% 이상 / 에디 INT 4% 이상 + 고정 마력 11 이상. %와 고정값은 별도 옵션이다. 정확 문구/개별 줄을 고르던 ‘실제 옵션’ UI와 후처리 필터를 제거했다. 최소 합계 조건을 경매장 요청 본문에 직접 보낸다.
- 같은 옵션을 여러 번 입력하면 가장 높은 최소치 하나로 정리한다. 잘못된 키·음수·빈 값·비정상 숫자·잠재 없음과 양수 옵션의 모순은 조회 전에 거절한다. 각 영역의 조건은 최대 8개다.
- 기본 예산 200억 이하, 직접 최소/최대 범위, 사용자 지정 비율, 한쪽 경계 해제를 제공한다.
- 감시 OFF는 한 번 조회 후 종료한다. 기존 감시에서 OFF로 바꾸거나 행을 삭제하면 해당 감시만 중지한다. 다른 감시는 유지한다.
- 인증 오류, 과도한 결과, 연속 조회 제한, 일일 한도, 조건 거절을 구분해 안내한다. 검색 POST는 401을 포함해 자동으로 재전송하지 않는다. 인증이 만료됐으면 ‘계정 다시 연결’을 누른다. 이 동작은 현재 감시를 중지하고 공식 로그인 화면을 다시 연다.
- 비교는 API 총스탯에 장비·세트 변화량을 적용하며 크확은 전후 모두 100%로 고정한다. 대상 보스 방어율을 지정하고 상태이상 추가 데미지는 항상 적용한다. 상세의 ‘계산 근거’에서 각 계수 전후 값과 제외 범위를 확인한다. 캐릭터 응답은 15분 후 갱신한다. 일반·에디의 쓸만한 스킬 부여 줄은 발동 효과를 계산하지 않는다. 다른 잠재와 스탯은 그대로 반영하고 자세히 보기에서 제외한 줄을 알려준다. 쿨감·스킬 레벨·특수 반지 등 별도 모델이 필요한 변화는 여전히 미계산 이유를 표시한다.

## 2026-11-07 운영 수정

- 드래곤마스터의 유산 같은 서적 보조무기를 보조무기 슬롯에 매핑한다. 현재 슬롯이 비어 있으면 추가 장착으로 비교한다. 비교할 수 없는 경우 목록과 자세히 보기에 부위·직업·스탯·특수 공식 등 실제 실패 이유를 표시한다. 경매장 전투력 차이는 별도 제공 참고치로 구분한다.

- Discord OAuth 연결 인원 초과는 별도 안내 페이지로 표시한다. 운영 포털 인원 기본값은 4명이며, 서버 환경의 `MAPLE_PORTAL_USERS`로 조정한다.

## 2026-11-04 옵션 상한·정렬·시드링 변경

- 잠재·에디의 숫자 옵션별 합산 상한을 최대 8개씩 입력한다. 숫자 상한을 검증할 수 있는 옵션만 목록에 표시한다. 경매장에는 최소치만 보내고, 받은 매물의 실제 잠재 줄을 합산해 상한 초과를 제외한다. 상세 잠재 줄이 없거나 해석할 수 없으면 통과로 추정하지 않고 별도로 집계한다. 화면은 조회 건수·통과·초과·확인 불가를 구분한다. 검색 결과가 10,000건을 넘거나 수집이 중단되면 상한도 수집된 범위에만 적용된다.
- 기본 가성비는 예상 피해 증가율 ÷ 가격(억)이며 성능 비교를 끈 조회에서는 가격 낮은 순으로 돌아간다. 전투력 증가량 정렬은 경매장 응답의 `attackPowerDiff`를 수집된 결과에서 직접 정렬하고, 값이 없는 매물은 뒤로 보낸다. 예상 피해 증가율 정렬은 별도 독립 모델의 결과다.
- 시드링 선택과 발동 순간 비교 입력은 제거했다. 한 종류만 가정하던 이전 입력은 저장돼 있어도 새 조회에 적용하지 않는다. 시드링 장비 교체 자체는 발동 조건·지속 시간 모델이 없어 성능 비교 미지원으로 표시한다. 일반 장비 교체 비교는 캐릭터 API 기준 스탯의 장비 변화량을 반영하지만 쓸만한 스킬 부여 줄의 발동, 스킬별 회전율, 쿨타임 변화, 보스 패턴·직업별 실전 딜 비중까지 모두 계산하지는 않는다.
