# 검색·도감·데미지 계산 수정 기록

## 재현한 원인과 수정 순서

1. 도감 생성이 공식 자동완성과 과거 KMS 389 분류 자료의 내부 조인이다. 공식 목록에 있는 에테르넬 신발·장갑·망토 15종이 구버전 분류에 없어 삭제됐다. 공식 업데이트 749의 명칭·요구 레벨과 자동완성의 실제 식별자를 결합해 보완하고, 원본에 있는 에테르넬 전 항목의 포함을 검사한다. 이름이 같지만 성별/레벨/ID가 다른 항목을 무조건 합치지 않으며 같은 ID의 중복만 제거한다.
2. 잠재 입력이 단일 합산 최소값과 정확 문구의 개별 줄 조건으로 이원화됐다. 예를 들어 크뎀 합계 15%와 정확한 8% 줄을 동시에 요구했다. 정확 문구 선택 UI를 제거하고 `potentialOptions[]`, `additionalPotentialOptions[]`의 독립적인 여러 최소 합계 조건으로 통합한다. 사용자의 예시는 일반 `{criticalDamagePercent:15,intPercent:10}` AND 에디 `{intPercent:4,magicAttack:11}`이다. 이 조건을 제공자 요청 본문에 직접 전달한다.
3. 솔 조각은 동일 base ID에 live/sold를 붙이는 설계인데 normalizeJobs는 base ID만으로 중복 검증했다. 검증·저장·복원 모두 `(id, mode)`를 식별자로 사용한다. 검색 생성 실패는 인증 만료·한도·너무 넓은 범위·일시 제한·조건 오류로 구분하고, POST 실패를 자동 재전송하지 않는다. 결과 없는 상태/재시작 후 상세 목록 없음도 분리한다.
4. 비교 모델은 크리티컬 발동 확률을 사용하지 않았고, 재구성한 스탯과 실제 API 스탯을 대조하지 않았다. 기본 평균 크뎀 35%는 이미 기본 스탯에 포함되므로 다시 더하지 않는다. 기대 크리티컬 계수는 `1 + clamp(크확,0,100)/100 × (35 + 추가크뎀)/100`이다. 목표 방어율, 동일 조건에서의 계수와 장비/세트 교체 효과를 계산하고 실제 캐릭터 기준 정보·각 계수·지원 범위를 노출한다. 장비별 계산 실패는 해당 매물만 제외하고 다른 매물 계산을 유지한다. 지원되지 않는 효과를 0% 개선으로 포장하지 않는다.
5. ‘선택’은 검색 행 포함 여부였다. ‘이번 검색에 포함’으로 이름과 설명을 바꾸며 장비 선택/감시 여부와 구분한다. 체크 해제한 행의 검증·조회는 실행하지 않는다.

## 검증 기준

- 에테르넬 공식 이름 전수, 5직업군×신발/장갑/망토, 부위/직업 필터, 모든 페이지의 합과 항목 수, 동명·동일 ID 구분.
- 일반 크뎀15+INT10, 에디 INT4+고정마력11의 요청 본문; %/고정값 구분; 잘못된 키·중복 조건·음수·NaN·모순 등급·기존 설정 이관; 미선택 행 제외.
- live/sold 동일 base ID 허용, 동일 (id,mode) 거절, 중복 클릭/진행 중 재요청, 검색 실패 후 자동 POST 0회, 솔 조각 두 검색 생성 및 결과 분리, 다른 감시 유지.
- 데미지: 동일 교체 0%, 마법 직업의 마력/공격력 구분, 크확 0/50/100/초과, 방무 곱연산과 방어율 경계, 최종뎀 곱연산, % 적용 제외 스탯, 세트 변화/미지원 효과, 0 기준과 잘못된 수치, 캐시 유효기간, 매물 하나의 실패 격리.
- 화면 조작·실제 계정 검색은 사용자가 수행한다. 이번에는 정적 코드·HTTP 고정 응답·실제 요청 본문·숫자 검증을 실행한다.

## 수식 근거와 적용 한계

- [공식 스탯 가이드](https://maplestory.nexon.com/Guide/N23GameInformation/Articles/390): 최종뎀/방무는 곱연산, 크확 상한 100%, 기본 크리티컬 추가 피해 20~50%.
- [공식 에테르넬 추가 공지](https://maplestory.nexon.com/News/Update/749): 250레벨 신발·장갑·망토 15종 및 추가 세트 단계.
- [DPM 계산기 원본](https://github.com/oleneyl/maplestory_dpm_calc/blob/master/dpmModule/kernel/core/modifier.py): 주/부스탯, 공마, 크리티컬 기대값, 데미지·보공, 방무 계수의 독립 구현을 대조한다. 과거 버전의 직업 스킬 수치는 현재 게임 자료로 사용하지 않는다.
- [simaple 원본](https://github.com/simaple-team/simaple/blob/main/simaple/core/base.py): 개별 최종뎀·방무의 합성 연산을 대조한다.

계산값은 동일 공격·대상·버프 조건에서의 장비 교체 기대 피해 계수의 상대 변화다. 전투력·환산 점수나 전투 전체 DPM과 같지 않다. 쿨감·버프 지속·스킬별 방무/크확·회전율·특수 장비·데미지 상한 등의 변화는 별도 스킬/전투 모델 없이 정확한 전체 증가율로 환산하지 않는다. 계산 근거와 누락을 출력하고, 정확하게 반영할 수 없는 항목은 수치 대신 이유를 반환한다.


## 구현 및 검증 결과

에테르넬 누락 15종 보완 후 도감 5,756개. 공식 에테르넬 이름 전수와 부위·직업군·페이지 중복 검사를 통과했다. 최소 합계 조건은 일반/에디 배열로 정규화되어 실제 전송되는 JSON 본문까지 확인했다. 솔 조각 두 모드는 HTTP 제출→실행→결과 저장→재시작 상태 복원에서 분리되며, 미선택된 잘못된 행이 조회를 막지 않는다.

예외 검사에서 하위 어댑터의 401 쓰기 자동 재전송도 발견해 GET만 복구하도록 수정했다. POST 실패 시 자동 검색 재시도 0회를 검증했다. 솔 조각의 불필요한 스타포스 0 필터를 제거했다. 메모리/디스크 캐시 만료 시각도 같은 타임스탬프를 사용한다.

데미지는 재구성값이 실제 총스탯과 다름을 확인했으므로 API 기준값에 장비/세트의 변화량만 적용하도록 수정했다. 기존 스탯%·공마%·% 미적용 스탯 분해가 정확하다는 전제가 필요하며, 전체 DPM까지 검증됐다고 주장하지 않는다. 세부 수식·제외 조건은 [DAMAGE_MODEL.md](DAMAGE_MODEL.md)에 기록했다.

최종 Node 24 격리 컨테이너 자동 검사 63개 통과. 외부 네트워크를 차단해 실제 계정 검색이 발생하지 않도록 했다. HTTP 경로와 요청 본문을 포함한다. 별도로 기존 캐릭터 캐시를 읽기 전용으로 마운트하고 캐시가 수집된 시점의 가짜 시간에서 오프라인 숫자 검증을 했다: INT 59,318/마력 7,544가 API 기준값과 일치, 동일 교체 0%, 크뎀만 8% 추가한 경우 3.25%. 이는 저장 당시 자료 검증이며 현재 실시간 캐릭터/실제 매물 검증이 아니다. 화면 조작·스크린샷 검사는 이번 요청대로 실행하지 않았다.


## 후속: 마법사 매물 검색 HTTP 400

저장된 실패 조건은 에테르넬 메이지글러브/장갑, 마법사, 200~700억, 17성 이상, 레전드리, 크뎀 합계 15%였다. 공식 경매장 공개 번들을 2026-11-04 다시 읽어 확인한 직업군 API enum은 FIGHTER/WIZARD/ARCHER/THIEF/PIRATE다. UI와 로컬 카탈로그는 WARRIOR/MAGE를 쓰는데 요청 어댑터가 이를 그대로 전송했다. 마법사와 전사의 코드 변환 누락을 수정했다. 실패 조건의 나머지 값을 유지한 채 실제 전송 JSON에 WIZARD가 들어가는 회귀 검사를 추가했다. 사용자 계정 검색 POST를 재실행해 확인하지는 않았다.

근거: https://auction.maplestory.nexon.com/assets/index-DPLLR4h6.js 의 Na 및 KMe 직업군 매핑. 오류 메시지가 조건명을 특정하지 않는 이유는 당시 저장 상태에 HTTP 원문/필드 정보가 보관되지 않았기 때문이다.
